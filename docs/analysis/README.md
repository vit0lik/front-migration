# Анализ базы данных Front

## 1. Анализ закупки продукции
**Основные и связанные таблицы:**
* `bm_StorageOperations` (Строки закупки)
  * `ID` — номер строки (Пример: 4780421)
  * `DocumentID` — номер документа (Пример: 388235)
  * `OperationID` — тип операции (Пример: 1)
  * `ProductID` — код товара (Пример: 4368)
  * `VendorID` — код поставщика (Пример: 200)
  * `Count` — количество (Пример: 2.7640)
  * `Amount` — сумма (Пример: 892.77)
* `bm_StorageOperationsType` (Типы складских операций)
  * `ID` — код операции (Пример: 1)
  * `Description` — название (Пример: Поступление)
  * `Factor` — знак движения (Пример: 1)
* `product` (Справочник товаров)
  * `id` — код товара (Пример: 4337)
  * `description` — название (Пример: Бананы)
  * `CategoryID` — код категории (Пример: 200)
  * `onhand` — остаток в карточке товара (Пример: пусто)
* `vendors` (Справочник поставщиков)
  * `id` — код поставщика (Пример: 211)
  * `firstname` — название (Пример: Пятая Армия)
  * `clientgroup` — код группы (Пример: 32)
  * `IsUse` — признак использования (Пример: 1)
* `storages` (Склады)
  * `id` — код склада (Пример: 41)
  * `description` — название (Пример: Склад)
  * `CompanyID` — код компании (Пример: 6)
* `bm_Companies` (Компании)
  * `ID` — код компании (Пример: 6)
  * `CompanyName` — название (Пример: ИП Лукьянова Анастасия Игоревна)
  * `INN` — ИНН (Пример: 380122679974)
* `category` (Категории товаров)
  * `id` — код категории (Пример: 147)
  * `description` — название (Пример: Мясные)
  * `categoryid` — код родителя (Пример: пусто)
* `pricelist` (Прайс-лист)
  * `id` — код записи (Пример: 113681)
  * `DocumentID` — номер документа (Пример: 142417)
  * `productid` — код товара (Пример: 4544)
  * `basecost` — цена (Пример: 140.00)
  * `vendorid` — код поставщика (Пример: пусто)
* `size` (Размеры и порции)
  * `ID` — код размера (Пример: 1)
  * `sizeid` — код (Пример: порция)
  * `description` — название (Пример: 100г)
  * `portionrate` — коэффициент порции (Пример: 100.000)

## 4. Анализ работы персонала
**Основные и связанные таблицы:**
* `personnel` (Сотрудники)
  * `personid` — код сотрудника (Пример: 906)
  * `firstname` — имя (Пример: Доставка)
* `bm_JournalSessions` (История действий и сессий)
  * `ID` — ключ события (Пример: 174072)
  * `PersonID` — код сотрудника (Пример: 897)
* `bm_BonusHistory` (История бонусов)
  * `ID` — ключ записи (Пример: 84860)
  * `PersonID` — кому начислен бонус (Пример: 906)
* `bm_ShiftsOperations` (Учет кассовых смен)
  * `ID` — номер смены (Пример: 65)
* `bm_WorkHours` (Учет рабочего времени)
  * `ID` — номер записи (Пример: пустая таблица)
* `bm_ShiftsOperations_Values` (Значения кассовых смен)
  * `ID` — код записи (Пример: пустая таблица)
  * `ParentID` — код смены (Пример: пусто)
  * `Value` — значение (Пример: пусто)
* `personnelmessages` (Сообщения сотрудникам)
  * `id` — код сообщения (Пример: 1)
  * `personfrom` — от кого (Пример: 0)
  * `personto` — кому (Пример: 1)
  * `messagetime` — время (Пример: 2008-03-25 15:44:02.157)
  * `message` — текст (Пример: KLJFKFJKSFJKSDKF)
* `bm_CashOperations` (Кассовые операции)
  * `ID` — код операции (Пример: пустая таблица)
  * `OperationTypeID` — тип операции (Пример: пусто)
  * `Amount` — сумма (Пример: пусто)
  * `PersonID` — код сотрудника (Пример: пусто)
* `bm_CashOperationsType` (Типы кассовых операций)
  * `ID` — код типа (Пример: 1)
  * `Description` — название (Пример: Принято по смене)
